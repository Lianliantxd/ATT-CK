# LLM-based interpretation of cyber attack manifestations

This repository contains scripts to process and analyze the [Cyber Attack Manifestations - Log Data Set (CAM-LDS)](https://zenodo.org/records/18390560) using LLMs.

If you use data or scripts from this repository, please cite the following publication:
* M. Landauer, W. Hotwagner, T. Boenke, F. Skopik, M. Wurzenberger. 2026. [CAM-LDS: Cyber Attack Manifestations for Automatic Interpretation of System Logs and Security Alerts](https://doi.org/10.1007/s10207-026-01318-x). International Journal of Information Security, 25(5). \[[PDF](https://link.springer.com/content/pdf/10.1007/s10207-026-01318-x.pdf)\]

## Getting the data

We provide a data set of filtered attack manifestations online. Download and unzip it with the following commands:

```
wget https://zenodo.org/records/18390561/files/manifestations_filtered.zip
unzip manifestations_filtered.zip
```

In the `manifestations_filtered` directory you can find log data and security alerts generated by various cyber attacks. The manifestations are collected for single attack `steps`, `sequences`, and `techniques`. We recommend to focus on attack steps, since each step may be associated with multiple techniques and thus both sequences and techniques directories contain duplicated logs.

For example, Step 4 of Scenario 1 is a web scanning attack; check out our [publication](https://doi.org/10.1007/s10207-026-01318-x) for state charts of all scenarios. You can find the logs corresponding to that attack step as follows:

## Creating LLM Prompts

To create LLM prompts based on the log data in the `manifestations_filtered/steps` directory, use the following script. Using the displayed example, five prompts are generated per step by randomly selecting scenario variants. Note that log lines are sampled only once per scenario variant and step, meaning that selecting the same variant multiple times results in identical prompts rather than new random samples of log lines. Using this command together with the random seed of 42 reproduces the `llm_queries.json` file provided in this repository.

```
python3 create_llm_prompt.py --samples 5 --seed 42
```

Note that `llm_queries.json` was created from version 1 of the data set ([record 18390561](https://zenodo.org/records/18390561), as downloaded above). The latest version 2 ([record 18861762](https://zenodo.org/records/18861762)) additionally contains audit events of `runc init` in the Docker `audit.log` files of steps 3, 6, 8, 10, and 13 of Scenario 7, which results in different prompts. Moreover, `Path.rglob` does not return the log files in a fixed order, so the prompts may also differ across file systems and Python versions; the provided file can be reproduced with Python 3.12 when the files are read in the order in which they are stored in the zip archive.

The generated prompts contain a general task description as well as the lines to be classified. An example could look like this:

```

You are provided with samples from one or more hosts and one or more log sources that are captured during execution of one specific MITRE ATT&CK technique. Always output a valid JSON object with the following fields:
 - "techniques": A list of top 10 ATT&CK techniques that are most likely related to the sample logs, sorted in descending order. Only print the ID of the techniques without any other descriptions.

  logs/access.log.1:
```

To create prompts with new random samples of log lines in every repetition, as described in Sect. 5.1.2 of the paper, use the following script instead. It works like `create_llm_prompt.py` and takes the same parameters, but samples the log lines again for each prompt of a step. Prompts of steps where no log file has more than ten lines may still be identical, since all lines are included in this case. This command will create the file `llm_queries_resampled.json`. Since `get_llm_responses.py` reads the prompts from `llm_queries.json`, add `--output llm_queries.json` to retrieve responses for the new prompts (this replaces the provided file).

```
python3 create_llm_prompt_resample.py --samples 5 --seed 42
```

## Retrieving responses from an LLM

To query the LLM with the prompts generated in the previous section, use the following script. Note that you need to set your `OPENROUTER_API_KEY` before running this scipt.

```
python3 get_llm_responses.py
```

This command will create the file `llm_responses.json`. Each line in this file is a json object that includes information on the scenario, variant, and step of the attack chain, as well as the prompt, response, and ground truth labels.

Responses from the LLM include the predicted attack techniques for the log data, an estimation whether the logs correspond to benign or malicious behavior, and an explanation. An example could look like this:

```
"techniques": ["T1059.004", "T1190", "T1068", "T1105", "T1041", "T1071.001", "T1055", "T1036", "T1005", "T1043"],
"confidence": "Somewhat Certain: Attack",
"explanation": "Web access to ZoneMinder (/zm/index.php) is followed by auditd showing apache2 (www-data) spawning /bin/sh with a \"sh -c\" command, which is a strong indicator of command execution via a web application (likely exploitation). The proximity of the remote client IP to the PHP warning and the shell exec makes this more consistent with attacker-driven activity than normal web usage."
```

*Clarification regarding the stability results in our paper*: The paper refers to generating prompts "with new random samples of log lines." However, log lines are sampled only once per scenario variant and attack step, and reused whenever the same variant is selected. Consequently, the five repetitions resulted in identical prompts for 89 of the 198 attack steps, while prompts varied for the remaining 109 steps. This distinction is important when interpreting the Same-Top-1 stability results: for identical prompts, the metric reflects run-to-run consistency rather than robustness to different log samples. In particular, Llama-4's higher overall stability compared to GPT-5.5 (68.2% vs. 59.1%) is entirely attributable to the identical-prompt subset (83.1% vs. 62.9%), whereas both models achieve 56.0% on steps with varying prompts.

The numbers in this clarification can be reproduced with the following script. It counts the distinct prompts of each attack step in `llm_queries.json`, uses the log files in `manifestations_filtered/steps` (if available) to check whether a new sample could have resulted in different log lines, and computes Same-Top-1 separately for steps with identical and with varying prompts in `llm_responses.json`. Use `--queries llm_queries_resampled.json` to check prompts created with `create_llm_prompt_resample.py`, and `--csv <file>` to write the results for each step to a file.

## Reproducing the data set: Extraction of attack manifestations (optional)

The filtered attack manifestations are based on log data collected from multiple simulation runs. We recommend to just use the filtered manifestations as described in the previous sections; however, we also provide the script used to generate these manifestations.

First, you need to download the logs collected from all simulation runs from our [Zenodo page](https://zenodo.org/records/18390560) and store them in a directory called `data/scenario<id>` within this respository (you need to create these folders). For example, for the simulations in Scenario 2, the following files should exist:

```
data/scenario2/scenario_2_cron
data/scenario2/scenario_2_rootkit
``` 

Note that filtering is based on the normal behavior activities observed in all of the available scenarios; therefore the resulting manifestations may differ if not all 34 simulation runs (18 from Scenario 1, 2 from Scenario 2, 6 from Scenario 3, 1 from Scenario 4, 1 from Scenario 5, 5 from Scenario 6, and 1 from Scenario 7) are in their respective directories. Then, run the following command to extract the attack manifestations - this command will generate the `manifestations_filtered` and `manifestations_raw` folders.

```
python3 extract_attack_logs.py
```

Besides the manifestations, the script creates the files `labels.json` and `attack_times.csv` provided in this repository. `attack_times.csv` lists the start and end times (Unix timestamps) of the attack steps together with their techniques and tactics. Note that in rows with more than one technique (203 of the 904 rows), the `tactics` column concatenates the tactics of the individual techniques without separator, e.g., `reconnaissancereconnaissance` for the techniques `T1590.002_T1591`, while tactics of the same technique are separated by `_`. The tactics of each technique are available in the `metadata` field of the corresponding entry in `labels.json` (key `<scenario>-<event_id>`). The `technique_names` column is not filled (`NA`).
