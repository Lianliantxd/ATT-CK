可以结合，而且我们已经有比“从 50 篇论文里挑一个模型套到 CAM-LDS”更明确的切入点：

> **保留已有 GTE 对未见技术的语义识别能力，同时利用 Seen 技术的监督信息提升表现；再检查模型是否真正使用了区分攻击技术的日志证据。**

但要先指出一个前提：**现在还不能确定，我们的主要瓶颈一定是模型结构。** 现有结果同时暴露了排名问题、知识版本问题和参考资格问题。文献能帮助提出可检验的方法，不能直接证明哪个因素导致了历史错误。

我建议把现有工作和文献结合成一条主线：**先修好评价合同，再做最小方法对照，最后验证是否真的识别了行为证据。**

## 二、论文告诉我们：下一步不应该只继续调 Seen 偏置

我们已经对 450 条含 Unseen 目标的查询做过排名诊断。按当时 ONE 协议：

- 冻结 GTE 在全 216 候选的 Top-10 中命中 66 条；
- 漏掉 384 条；
- 这 384 条里，有 **349 条**的正确 Unseen 技术，即使只看 Unseen 技术内部排名，也没有进入前 10；
- 另有 **35 条**在 Unseen 内部有进入前 10 的可能，但被 Seen 技术挤出全候选 Top-10。

这意味着：

> 对那 349 条，只改变 Seen 与 Unseen 两组之间的分数高低，并保持 Unseen 内部顺序不变，无法把正确技术送进全候选 Top-10。

这是已有排名的数学边界，**不是说这些案例一定存在可供模型识别的正确行为证据**。[失败机制诊断报告](/Users/tianxd/Documents/mid-term/research3_open_vocab_failure_mechanism_diagnosis01/R3_OPEN_VOCAB_FAILURE_MECHANISM_DIAGNOSIS_RESULTS.md)

因此，研究路线应拆成两个问题：

1. **跨组竞争问题**：Seen 分数过强，压住 Unseen；这部分可以用校准、融合等方法研究。
2. **Unseen 内部排序问题**：正确技术排在大量其他未见技术之后；仅靠 Seen 偏置调整无效，需要检查技术定义、日志证据及表示能力。

目前我们的实验表明，第二类问题不能被忽略。

## 三、我建议的主研究方向：保留标签语义的领域适配

### 1. 从哪篇论文得到启发？

[NAACL 2025 Findings 的多标签文本论文](https://aclanthology.org/2025.findings-naacl.315/)发现：监督训练可能提高整体任务表现，却损害未见标签的预测能力。它提出冻结标签编码器，并结合辅助学习，尽量保留零样本能力。

这和我们看到的现象相似：

```text
冻结 GTE：
    Seen 较弱
    Unseen 有一定能力

监督适配：
    Seen 变强
    Unseen 排序明显退化
```

但只能说**现象相似**，不能因此断言论文已经解释了我们的失败。尤其 B3 本来就没有 Unseen 类分类器；B4/B5 的退化原因也尚未被单独隔离。

### 2. 怎么和我们的 GTE 结合？

把当前流程理解为：

```text
日志文本 ──日志编码器/投影──→ 日志向量
                                      ├─ 相似度 → 216 个技术排序
技术定义 ──技术编码器/投影──→ 技术向量
```

我们已有的 B4/B5 更新了日志侧和技术侧的投影头；GTE 主干保持冻结。可以设计一个更小的对照：

```text
方案 A：两个投影头都训练
        对应已有 B4/B5 方向

方案 B：技术侧语义表示保持冻结
        只训练日志侧轻量适配

方案 C：技术侧冻结，只训练日志侧，
        并约束新分数不要完全偏离原冻结 GTE 的排序
```

直观理解：

- **技术侧冻结**：尽量保留每种 ATT&CK 技术在原语义空间里的位置；
- **日志侧适配**：让安全日志更容易靠近对应技术定义；
- **保留原排序的约束**：防止新监督信号把原本有用的未见类关系完全压掉。

但这只是一个**候选设计**，不是确保有效的公式。日志侧被过度训练，同样可能破坏其与冻结技术空间的匹配。

### 3. 它和我们已有工作有什么实质区别？

| 已有工作 | 做法 | 新对照的重点 |
|---|---|---|
| 冻结 GTE | 两边都不适配 | 作为未见能力参考 |
| B3 | 训练已见类线性分类器 | 作为 Seen 强基线，但没有未见类分类器 |
| B4/B5 | 训练日志侧与技术侧投影 | 检查双侧适配后的 Seen/Unseen 结果 |
| C3/C4 | 事后融合或校准已有分数 | 不改变 GTE 内部的 Unseen 排序 |
| **候选单侧适配** | 固定技术表示，只适配日志侧 | 单独检验“技术语义漂移是否参与退化” |
| **候选保留约束** | 适配同时约束相对原 GTE 的变化 | 检验保留原语义排序能否改善联合权衡 |

这里真正的研究问题不是“我们也用冻结标签编码器”，因为这已经有论文提出。可能的贡献只能来自：

1. 把它严格适配到 ATT&CK 日志—技术识别；
2. 证明它在多标签、结构化技术空间中的适用边界；
3. 分析它能否解决我们实际观察到的特定退化；
4. 超过公平条件下的简单强基线。

**是否具备足够的方法新颖性，目前还不能保证，需要进一步对照完整相关工作。**

## 四、第二个组件：从“整体相似”转向“候选技术的证据匹配”

如果单侧适配能缓解退化，仍未必能解决 Unseen 内部排序。我们还需要问：

> 模型是在识别日志中的关键行为，还是只在匹配技术名称、工具名称和通用词汇？

可以借鉴医疗编码和细粒度语义对齐论文，设计**技术条件化的证据匹配**。

### 一个示意例子

假设某条日志包含：

```text
进程 A 执行某命令
命令访问了对象 B
日志记录了操作请求，但没有记录执行结果
```

假设有两个竞争技术：

```text
技术 X：
  定义中的关键动作与 A、B 对应

技术 Y：
  使用相似工具，但要求另一种动作或操作对象
```

现有整体向量检索可能因为工具名称相近，把 X 和 Y 排得很接近。

候选方法可以分别比较：

| 比较维度 | 要回答的问题 |
|---|---|
| 动作 | 日志是否记录技术定义所需的动作？ |
| 对象 | 操作对象是否一致？ |
| 条件 | 有无技术定义所需的必要前提？ |
| 结果 | 只记录尝试，还是记录了成功结果？ |
| 竞争区分 | 哪一条证据能支持 X 而不能同样支持 Y？ |
| 信息缺口 | 当前日志是否缺少判断所需字段？ |

这里有两个重要限制：

- **没有记录结果，不等于操作没有成功。**
- **当前视图没有证据，不等于完整攻击中没有发生。**

这个组件的作用不是强迫模型给出一个答案，而是让它区分“支持”“部分支持”和“当前信息不足”。

### 与已有机制表示实验的区别是什么？

我们之前已经做过多个机制视图、知识视图和 GTE 对照。因此不能简单地把“提取动作、对象”重新命名为新方法。

只有在下面条件成立时，这个方向才有研究增量：

1. 使用与基线**相同的日志内容**；
2. 使用同一版本、同一预算的技术定义；
3. 独立参考确认该日志确有区分证据；
4. GTE、词法强基线和 C3/C4 在该案例上仍然失败；
5. 新方法能指出具体证据，并且排序或判断确实改进；
6. 去掉证据对齐组件后，收益消失或明显减弱。

否则，很可能只是在不同包装下重复已有实验。

### 第一阶段：先固定数据和评价合同

这是目前最优先的工作。

- 既有范围疑问仍需独立裁定。

报告给出的当前决策是 **`GO_AFTER_LABEL_SCOPE_ADJUDICATION`**。[来源恢复报告](/Users/tianxd/Documents/mid-term/research3_open_vocab_source_recovery01/SOURCE_RECOVERY_REPORT.md)

这一步需要决定：

1. 研究要评价**保留原作者标签的历史任务**，还是评价**迁移到新版 ATT&CK 的新任务**；
2. 如果使用 19.2，撤销 ID 如何处理；
3. 每个 Gold 标签对应父技术还是子技术；
4. 同一查询涉及多个技术时，评价单位是什么；
5. 模型看到的技术定义、日志文本和候选集合是否对所有基线一致。

我建议先保留两套清楚分离的合同：

- **合同 A：历史复现合同**——保留原候选和作者标签，明确来源与版本局限；
- **合同 B：新版本研究合同**——明确采用何种知识版本及独立裁定后的映射。

两套合同可用于研究版本影响，**不能直接把新定义下的结果说成比旧定义下的方法提升了多少**。

### 第二阶段：建立小规模、预测隔离的人工证据参考

现有 384 条是按 GTE 未命中筛选、且已经曝光的开发案例；它们适合帮助我们理解问题，**不能变成独立测试集**。

我建议先以“逻辑步骤”为主要组织单位，而不是把同一步骤的多个查询视图当作互相独立的攻击案例。可以从已有案例中**分层抽取一个可管理的首批人工审查集**，数量由可用审查资源决定，重点覆盖：

- AI 提示可能有相关行为证据的案例；
- 当前日志视图不足的案例；
- Gold 技术范围或粒度存疑的案例；
- Seen、Unseen 及混合标签案例；
- 不同攻击场景和不同技术；
- 已经命中与未命中的案例。

审查者应看到：

```text
当前允许使用的日志证据
+
冻结的候选技术定义
+
可追溯的技术范围说明
```

审查者不应看到被评价模型的排名，至少在首次独立判断时不看。记录：

- 证据是否支持目标技术；
- 证据是否足以区分主要竞争技术；
- 日志缺少什么；
- 是否只能判断为部分支持或不可评价；
- 审查者之间是否存在分歧及仲裁结果。

这里要把两类参考分开：

1. **开发诊断参考**：可从 384 条等已曝光案例中建立，用于定位失败；
2. **独立确认参考**：来自未参与模型选择的独立攻击执行、场景或合格外部数据，用于最终检验。

不能只挑 GTE 已经失败的案例，就把该子集上的改善称为全体任务提升；这会产生选择偏差。

### 第三阶段：开展最小方法实验

完成前两阶段后，再决定是否启动模型实验。

建议的最小对照如下：

| 组别 | 方法 | 它回答的问题 |
|---|---|---|
| 1 | 全候选 BM25/字符词法基线 | 简单文本匹配能做到什么程度？ |
| 2 | 冻结 GTE | 原始开放语义能力是多少？ |
| 3 | B3 线性分类器 | 有监督 Seen 能力上限之一是多少？ |
| 4 | B5 或已有开放描述投影 | 既有对比学习能做到什么？ |
| 5 | C3 | 简单融合能做到什么？ |
| 6 | C4 | 偏置校准比简单融合是否更好？ |
| 7 | 单侧适配 | 固定技术侧是否有助于保留 Unseen？ |
| 8 | 单侧适配＋保留约束 | 约束原语义排序是否带来额外收益？ |
| 9 | 在合格案例上加入证据匹配 | 能否进一步改善有明确区分证据的案例？ |

**公平比较条件：**

- 所有方法使用同一批允许的日志内容；
- 使用同一个技术定义版本；
- 候选空间一致；
- 划分方式一致；
- 不用测试 Gold 选择候选或参数；
- 如果方法额外使用人工条件、额外上下文或模型调用，要单独记录并比较成本；
- 单独评估候选召回与候选内排序，避免将“候选更多”误认为“排序理解更好”。

特别注意：历史词法基线与 GTE 的输入合同并不完全一致。方法门控报告记录，旧词法与 GTE 只有 **30/975 查询、41/216 知识文档**逐字相同；所以需要先在统一输入下重建公平比较，不能直接拿旧表格得出因果结论。[方法准入决策](/Users/tianxd/Documents/mid-term/research3_method_hypothesis_gate01/GO_NO_GO_DECISION.md)

## 六、怎样判断新方法真的成功？

不能只说“总体 MRR 提高了”。

我建议在看到独立测试结果之前，先冻结以下评价框架。

### 主要评价

1. **Unseen 目标 MRR@10 和 Top-10 命中率**；
2. **Seen 目标 MRR@10 和 Top-10 命中率**；
3. 保留全部候选技术共同参与排序；
4. 单独报告 Seen、Unseen 和 Mixed 查询；
5. 同时报告查询加权与场景等权结果。

这里的 Mixed 查询会同时进入 Seen 目标和 Unseen 目标统计，不能把两者样本数直接相加。

### 是否兼顾？

应该同时满足两类要求：

- 相比冻结 GTE，Unseen 有预先定义的、具有实际意义的改善；
- 相比 Seen 强基线，Seen 的下降不超过预先允许的范围。

具体阈值应在正式测试前根据应用要求、样本规模和验证集确定。**现在不应为了让某个历史方法通过而事后选阈值。**

### 什么时候说明假设不成立？

以下任一情况，都应认真考虑停止或修改方向：

- 单侧适配和 B5 效果相同，不能证明固定技术侧有价值；
- Unseen 提高完全来自改变 Seen 分数，Unseen 内部排序没有改善；
- Unseen 增益伴随不可接受的 Seen 损失；
- 收益只出现在已经反复查看过的开发案例；
- 简单 BM25、GTE 或 C3 就能复现全部收益；
- 人工复核发现案例本身没有足够证据，无法判断预测对错；
- 模型能输出解释，但解释没有对应到真实日志字段。

## 七、这项研究最后可以形成什么论文故事？

目前**还不能写成“我们提出的方法解决了 Seen/Unseen 权衡”**。但如果后续证据支持，可以形成一个比较清楚的研究故事：

### 研究问题

> ATT&CK 技术识别中，如何在利用已见技术监督信息的同时，保留对未见技术的识别能力？

### 现有观察

- 直接监督提高 Seen，但可能牺牲 Unseen；
- 简单融合能部分恢复 Unseen，但未达到预设的联合保持目标；
- 仅调 Seen 分数无法改变大量案例中的 Unseen 内部排序；
- 部分错误是否属于模型失败，还依赖定义和独立证据参考。

### 候选方法

- 固定或稳定技术语义表示；
- 对日志侧进行轻量适配；
- 对候选技术进行证据条件化判断；
- 必要时允许输出证据不足，而不是强制确定标签。

### 可能的贡献

只有实验通过后才能宣称：

1. 构建了合同清楚、评价单位明确的 ATT&CK 广义零样本评价；
2. 揭示了领域适配对 Seen/Unseen 排序的影响；
3. 提出并验证一种保留未见技术能力的方法；
4. 通过独立证据审查说明方法在什么情况下有效、什么情况下不可评价。

如果最终方法没有超过强基线，也仍可能形成有价值的**负结果与评价研究**；但能否达到目标论文的贡献要求，还要看独立数据、分析深度和相关工作对比。
